## 1. 분석 범위와 접근 가능 여부

| 경로 | 결과 |
|---|---|
| WebFetch · curl (일반 HTTP) | HTTP 429 Too Many Requests — 비브라우저 요청 차단. 우회하지 않음 |
| Claude in Chrome 확장 | 미연결 |
| REA `list_browser_targets` / `inspect_web_page` / `capture_web_screenshot` | **정상** — 사용자가 연 디버깅 포트 Chrome(155) 탭을 수동 관찰 |
| REA `capture_browser_scenario` (connect) | **실패** — `execution_failure` (provider `rea-playwright-browser-scenario`). 1초 대기만 넣은 최소 시나리오도 실패. 원인 미확정 (`rea doctor` 미실행) |

그래서 클릭 · 이동은 REA 가 하지 않았고, **사용자가 조작한 상태를 REA 로 수동 관찰**했다.

| 관찰 | 상태 | Evidence |
|---|---|---|
| ① 데스크톱 첫 화면 (929×925) | 초기 상태: 2박 선택 · 약관 미체크 · 아코디언 닫힘 | `ev_18823218…` (스크린샷), `ev_11ff46c6…` (접근성 노드 1,731) |
| ② 모바일 (375×874) | 사용자 조작 후: 31박 선택 · 약관 체크(사용자) · 상품 정보 아코디언 4개 펼침 | `ev_…1792781274986` 파일 (스크린샷), 접근성 노드 2,679 |

- 접근성 트리의 이름 있는 노드(① 592줄 · ② 661줄)와 두 스크린샷은 전부 읽었다.
- 스크린샷은 보이는 화면만 (REA 는 스크롤하지 않음).
- DOM 텍스트 원문 · 스크립트 소스 · 네트워크 본문은 REA 정책상 수집되지 않았다 (`policy_filtered`).
- 약관 체크는 **사용자가 직접** 한 것이다. 분석자는 약관 동의 · 장바구니 · 결제 · 개인정보 입력을 하지 않았다.
- 플랫폼: Shopify ([관찰] 스크립트 경로 `/cdn/shopifycloud/...`, 하단 "propulsé par Shopify").

## 2. 핵심 결과 요약

1. **[관찰] 대여가 현재 중단 상태다.** 제목 바로 아래 "12월까지 대여 일시 중단(인력 축소)" 안내가 있다. 그래서 실제 주문 흐름은 이번에 검증할 수 없었다.
2. **[관찰] 날짜가 아니라 '기간 묶음'을 고른다.** 2 · 7 · 14 · 21 · 31박 라디오 버튼이다. 상품 페이지 접근성 트리에 달력은 없다.
3. **[관찰] 가격은 사이즈 버튼에 "~부터"로만 보인다.** Cabine 19€~ · Medium 25€~ · Large 29€~. 31박을 선택한 상태에서도 기간별 가격 텍스트는 접근성 트리에서 찾지 못했다.
4. **[관찰] 장바구니 버튼은 약관 체크 전에는 비활성이고, 체크 후 활성화된다.** 약관 동의가 상품 페이지 단계에 있다.
5. **[관찰] 배송 · 반납 안내가 구체적이다.**
   - 출발 3~5일 전 무료 배송. 출발이 5일 이내면 즉시 발송.
   - 귀국 후 5일 안에, 받은 박스와 동봉된 반송 라벨로 택배 거점(point relais)에 반납.
6. **[관찰] 신뢰 요소를 여러 겹으로 쌓는다.**
   - Trustpilot 4.7/5 (400개 이상), 상품 리뷰 5.0 (9개, "Vérifié" 표시 + 운영자 답글)
   - 10년 보증, 내구성 인증 라벨, 팀 소개
   - 위생 설명, 구성품 목록, 사이즈별 권장 여행 기간
7. **[관찰] 모바일에서는 하단 고정 "장바구니 담기" 버튼이 스크롤 내내 보인다.** 이 버튼에 가격 표시는 없다.

## 6. UI/UX 분석

**레이아웃 · 정보 구조** [관찰]
- 2열 구성: 왼쪽 갤러리, 오른쪽 구매 패널.
- 패널 아래 순서: 서비스 이유 → 리뷰 → 이용 방법 3단계 → 제품 강점 → 리뷰 → FAQ → 약속(환경) → 판매 상품 → 상품 리뷰 → 결제 안내.
- 리뷰가 페이지 곳곳에 반복 배치된다.

**타이포그래피 · 색** [관찰]
- 굵은 대문자 섹션 제목에 이모지를 많이 쓴다.
- 주황색 강조색이 상단 배너 · CTA · 가이드 팝업 탭 세 곳에 쓰인다.

**시각적 우선순위** [관찰 + 추론]
- 상품 사진이 화면 대부분을 차지한다.
- 가격은 사이즈 버튼 안의 작은 텍스트뿐이다.
- [추론] 최종 금액을 모른 채 약관에 동의하고 장바구니로 넘어가는 구조다. 가격을 예측하기 어렵다.

**신뢰 요소** [관찰]
- 외부 평점, 인증 리뷰와 운영자 답글
- 보증, 인증 라벨, 팀 얼굴과 이름, 소재와 원산지 공개

**혼란 요소** [추론]
1. 대여 중단 안내가 있는데도 옵션을 고르고 약관에 동의하는 것까지 가능하다. 사용자는 끝까지 진행한 뒤에야 막힐 수 있다.
2. 날짜를 고르지 않고 기간만 고르므로, 배송일이 언제로 잡히는지 상품 페이지에서는 알 수 없다.
3. 판매 상품 목록, 뉴스레터, 가이드 팝업이 대여 흐름과 섞여 있다.

**접근성** [관찰]
- 색상과 기간이 radio 역할로 노출된다.
- 약관 체크박스의 접근성 이름이 내부 ID "izyTerms"로 노출된다. 스크린리더 사용자에게 의미가 전달되지 않는다.

## 7. RECARRY 적용 제안

> 아래는 **제안**이다. RECARRY 현황은 저장소 코드를 읽고 확인했다 (`src/pages/Product.tsx`, `src/components/BookingSummary.tsx`, `src/booking/steps/ConfirmStep.tsx`, `src/data/home.ts`, `src/data/carriers.ts`, `src/styles/pages.css`, `docs/POLICY.md`).

### RECARRY가 이미 앞서 있는 점 (유지)

| 항목 | RECARRY 현황 | Dot-Drops |
|---|---|---|
| 가격 투명성 | 날짜를 고르면 상세 패널에 기간 라벨과 총액이 바로 보임. 예약 확인 단계에서 대여 요금 + 보증금 = 결제 예정 금액 | 사이즈별 "~부터"만 보임 |
| 날짜 선택 | 상세 패널에 달력이 있고, 고른 날짜가 예약으로 넘어감 | 기간 묶음만 선택 |
| 개별 상태 공개 | Carrier ID별 5개 항목 검수 기록 (PASS / 재점검) | 새 제품 기준 정보만 |
| 모바일 고정 CTA | `.pd-bar`에 가격 + 예약하기 | 버튼만 (가격 없음) |
| 약관 동의 위치 | 예약 확인 단계 (상세 페이지에 마찰 없음) | 상세 페이지에서 동의해야 버튼 활성 |

→ 약관 동의를 상세 페이지로 옮기는 것은 **권하지 않는다**.

### 7.3 현재 단계에서는 보류할 기능

| 기능 | Dot-Drops 근거 | 보류 이유 |
